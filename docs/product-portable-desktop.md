# 便携桌面：单人多台设备的跨机窗口/任务路线（v1.1.0–v1.1.5）

| 项 | 内容 |
|----|------|
| 性质 | 产品路线规划，不含代码改动 |
| 日期 | 2026-11-11 |
| 主题 | 一个人有多台电脑，人不换地方时能在统一入口找到/切换/搬运窗口；人换设备时，工作现场跟着走 |
| 取代 | 此前的便携出差路线；本文只做“便携桌面”这一条场景线 |
| 证据口径 | pre-launch，以维护者自身真实使用为准；Star/Issue/外部用户数不作需求证据 |

---

## 0. 一句话

**便携不是“把更多硬件塞进包里”，而是“人走到哪台设备，工作现场跟到哪台”。**

这一条线只解决一个场景：**窗口/任务开在另一台机器上，你要找到它、切过去、或者把它带过来。**

---

## 1. 一个具体场景

你坐在台式机前：

- 台式机：浏览器、文档、微信。
- 笔记本：VS Code、终端、正在跑的构建。
- 平板/手机：一个没看完的网页、一张截图。

现在要改一行代码：

1. 键鼠切到笔记本；
2. 在笔记本的任务栏/桌面里找 VS Code 窗口；
3. 改完，切回台式机；
4. 想对照浏览器里的文档，又切回台式机；
5. 想把这行代码/终端输出带到笔记本，复制、切回、粘贴；
6. 如果离开书桌去沙发，只带笔记本，台式机上的浏览器/终端留在原地，工作现场断了。

**摩擦不是“键鼠切不过去”，而是“我不知道另一台开了什么、在哪、怎么把需要的那一个带过来”。**

---

## 2. 为什么现有工具不够

| 方案 | 能做什么 | 缺口 |
|------|----------|------|
| Synergy / Barrier / Deskflow | 一套键鼠切多台 | 只切输入；不显示另一台开了哪些窗口；不解决“找窗口/搬窗口” |
| 远程桌面 / 串流 | 看/控另一台整屏 | 一次只看一台；是“远程操作”，不是“本地统一列表”；不能把单个窗口带过来 |
| PowerToys / 系统任务栏 | 单机窗口管理 | 只看本机；跨机不可见 |
| 浏览器标签同步 | 同步网页 | 只同步浏览器，不同步 IDE/终端/资源管理器 |
| Windows“继续在 PC 上”/Apple Handoff | 少量应用接力 | 覆盖窄；跨品牌不行；不显示全部窗口 |
| 手动重开 | 打开文件/URL/应用 | 靠记忆；路径/目录/参数容易丢；不是“一键” |

**空位：跨品牌、本地、2–4 台设备、把“窗口清单 + 切换 + 搬运 + 分组 + 跟随”做成一层。** 这是现有键鼠共享工具都没有做的。

---

## 3. 新能力层：跨机窗口/任务

这不是“再做一个投屏/远程桌面”，而是新增一层**窗口/任务数据与动作**：

1. **看见**：每台设备把窗口/前台应用/标题/最近活跃时间报给统一入口。
2. **切换**：一个列表/快捷键，直接把焦点切到某台设备的某个窗口。
3. **搬运**：把某个窗口“送到”另一台——不是迁移像素，而是带着应用/文件/URL/目录重新打开。
4. **分组**：把跨设备的窗口组成一个“工作区”（开发/写作/演示），一键聚焦/恢复。
5. **跟随**：人从一台设备换到另一台，工作区/任务列表跟着走。

---

## 4. 版本规划（5 个能力版）

| 版本 | 新能力 | 一句话 | 估算 | 门禁（不过就停） |
|------|--------|--------|------|------------------|
| v1.1.0 | 跨机窗口清单 | 一个列表看到 4 台设备的窗口/前台应用，点击聚焦 | 2–3 周 | 每天用 ≥5 次；找窗口时间下降 ≥50% |
| v1.1.1 | 跨机任务切换 | 快捷键/搜索/最近/固定；切焦点不用切布局 | 2–3 周 | 每天 ≥10 次；切换成功 >95% |
| v1.1.2 | 窗口搬运 | 把窗口送到另一台，带着文件/URL/目录重新打开 | 3–4 周 | 每天 ≥1 次；重开成功 >80% |
| v1.1.3 | 工作区分组 | 跨设备窗口分组，一键聚焦/恢复（开发/写作/演示） | 3 周 | 每天 ≥2 个工作区；恢复 >80% |
| v1.1.4 | 便携桌面跟随 | 人换设备时，任务列表/工作区跟着走 | 3–4 周 | 每天 ≥1 次换设备；跟随可用 |
| v1.1.5 | 跨机任务栏 | 常驻托盘/任务栏，显示每台设备窗口数，快速跳转 | 2–3 周 | 每天 ≥5 次；不占屏 |

**总量**：约 15–20 周（4–5 个月，单人）。比 11 版路线更实，也更接近“一个人多台设备”的真实摩擦。

---

## 5. 各版详情

### 5.1 v1.1.0 跨机窗口清单

**新增什么**：

- 每台设备枚举窗口：应用名、窗口标题、是否前台、最近活跃时间、所属设备。
- 统一列表：按设备/应用/最近活跃排序；搜索标题；点击 → 聚焦到对应设备/窗口。
- 只读展示，不做搬运/分组。

**场景**：

- 你坐在台式机前，列表里直接看到笔记本上的 VS Code、终端；点一下，焦点过去。
- 4 台机器开了几十个窗口，不再靠“切过去再找”。

**为什么不是现有功能**：这是新的**跨机窗口数据层**，不是布局切换/投屏；它把“另一台开了什么”变成可见。

**为什么通用工具替代不了**：Synergy 只切输入；远程桌面一次看一台整屏；PowerToys 只看本机；没有跨 4 台的统一窗口列表。

**依赖**：每台设备一个轻量窗口枚举 agent（Windows 先做；Mac 用 Accessibility/CGWindowList；Linux X11 可做、Wayland 受限）；现有输入通道负责聚焦。

**门禁**：连续两周每天用 ≥5 次；“找窗口”时间下降 ≥50%；否则说明你窗口不够多/痛点不成立，停。

---

### 5.2 v1.1.1 跨机任务切换

**新增什么**：

- 全局快捷键打开“跨机任务列表”；搜索、最近使用、固定项。
- 切焦点：不切布局、不切整屏，只把键鼠/焦点送到目标窗口。
- 与现有布局联动：切换后键鼠归属自动跟随；返回键回到上一台。
- 失败提示：目标设备离线/窗口已关，给出替代（最近窗口/设备）。

**场景**：

- `Ctrl+Alt+Space` 打开列表，输入“term”，直接跳到笔记本的终端。
- 在台式机写文档，按快捷键切到笔记本 VS Code，改一行，再按返回键回来。

**为什么不是现有功能**：这是新的**跨机任务切换层**，不是给布局加一个快捷键；它按“窗口/任务”切换，不按“设备整屏”切换。

**为什么通用工具替代不了**：Synergy 按设备切；远程桌面按整屏切；没有“按窗口搜索/最近/固定”的跨机切换。

**依赖**：v1.1.0 窗口清单；全局快捷键；输入通道。

**门禁**：每天 ≥10 次；切换成功 >95%；否则说明快捷键/列表不顺手，先改交互，不进入搬运。

---

### 5.3 v1.1.2 窗口搬运

**新增什么**：

- “送到另一台”：把一个窗口的应用/文件/URL/目录带到目标设备，重新打开。
- 支持类型：浏览器 URL、VS Code 文件夹/文件、资源管理器路径、终端工作目录 + 命令（可选）、文档文件。
- 源端可选：保留 / 最小化 / 关闭。
- 失败清单：目标设备缺应用/路径不存在/权限不足，逐项提示。
- 明确边界：**不迁移应用内部状态**（未保存内容、滚动位置、调试会话），只重建“可重新打开的工作现场”。

**场景**：

- 把台式机的浏览器窗口“送到”笔记本，URL 直接打开。
- 把笔记本的 VS Code 文件夹“送到”台式机，用大屏继续改。
- 把终端的工作目录“送到”另一台，重新开一个同目录终端。

**为什么不是现有功能**：这是新的**窗口搬运动作层**，不是投屏/远程控制；目标端是本地重新打开，不是远程画面。

**为什么通用工具替代不了**：远程桌面是把画面过去；Handoff 只覆盖少量应用；没有“按窗口送应用/文件/URL/目录”的通用工具。

**依赖**：v1.1.0/1；应用启动/文件打开/URL 打开；路径映射。

**门禁**：每天 ≥1 次；重开成功 >80%；否则说明覆盖类型不够，先补类型，不做分组。

---

### 5.4 v1.1.3 工作区分组

**新增什么**：

- 把跨设备的窗口组成一个“工作区”：开发（IDE 在笔记本、终端在台式机、浏览器在平板）、写作（文档/浏览器/笔记）、演示（PPT/浏览器/投屏）。
- 一键聚焦：把键鼠/焦点按顺序送到各窗口；或同时高亮。
- 一键恢复：按描述重新打开缺失的窗口。
- 保存/命名/固定；可绑定布局。

**场景**：

- 上班点“开发”：笔记本 IDE、台式机终端、平板浏览器一起就位。
- 会议点“演示”：笔记本 PPT、台式机浏览器、平板批注。
- 下班点“写作”：只留文档/浏览器，其他最小化。

**为什么不是现有功能**：这是新的**跨机工作区分组层**，不是布局预设；它管“哪些窗口一组”，不是“屏幕怎么摆”。

**为什么通用工具替代不了**：PowerToys 工作区是单机；远程桌面是整屏；没有跨 4 台、按窗口分组的产品。

**依赖**：v1.1.0–1.2；窗口描述/恢复。

**门禁**：每天 ≥2 个工作区；恢复 >80%；否则说明分组不是你的工作方式，停。

---

### 5.5 v1.1.4 便携桌面跟随

**新增什么**：

- 人换设备时（切键鼠/合盖/带走笔记本），任务列表/工作区跟着走。
- “跟随模式”：在目标设备上显示最近工作区/固定窗口；一键把需要的那几个窗口带过来。
- 离开设备时可选“挂起/保留/关闭”，避免两边同时改同一文件。
- 与 v1.1.2 搬运联动：跟随不是复制画面，是按描述在目标端重开。

**场景**：

- 从书桌走到沙发，只带笔记本；台式机的浏览器/终端“跟着”到笔记本（按 URL/目录重开）。
- 从笔记本回到台式机，工作区切回大屏。
- 出差只带笔记本，酒店里把台式机的工作区带过来（需要连接）。

**为什么不是现有功能**：这是新的**工作现场跟随层**，不是远程桌面/同步盘；它跟的是“窗口/任务描述”，不是文件或画面。

**为什么通用工具替代不了**：Handoff 覆盖少量应用；远程桌面要一直连着；网盘只同步文件；没有“跨机工作区跟随”。

**依赖**：v1.1.3 工作区；连接/路径映射；设备切换事件。

**门禁**：每天 ≥1 次换设备；跟随可用；否则说明你其实不换设备，停。

---

### 5.6 v1.1.5 跨机任务栏

**新增什么**：

- 常驻托盘/任务栏：显示每台设备的窗口数/前台应用；点击展开跨机列表。
- 快速跳转：最近 5 个窗口/固定工作区。
- 设备状态：在线/离线/忙碌；不占主屏空间。
- 可关闭：不强制常驻。

**场景**：

- 不用每次按快捷键；看一眼托盘就知道笔记本上还有几个窗口。
- 一键跳到最近用的跨机窗口。

**为什么不是现有功能**：这是新的**跨机任务栏 UI 层**，不是单机任务栏；它聚合 4 台设备。

**为什么通用工具替代不了**：系统任务栏只看本机；远程桌面不聚合；没有跨机任务栏。

**依赖**：v1.1.0–1.4。

**门禁**：每天 ≥5 次；不占屏/不打扰；否则退回快捷键模式，不做常驻。

---

## 6. 不做什么

- **不做窗口像素迁移/完整应用状态迁移**：成本极高、兼容性差；只做“按描述重开”。
- **不做手机窗口化**：现有投影 + 回控已覆盖；不再包装成新功能。
- **不做文件搜索/剪贴板历史/通知中枢/访客互传**：已被现有能力或通用工具覆盖，或成本收益不成立。
- **不做多用户共用**：这不是“一个人多台设备”的场景。
- **不把 Mac/Linux 键鼠补齐、H.264/E2、UI 打磨写进这条线**：属于工程/维护。

---

## 7. 需要你确认（不确认就不排下一版）

1. **这个场景对你真实吗？** 你是否经常遇到“窗口开在另一台，要切过去找/带过来”？如果一个月都没有几次，这条线不成立，直接停。
2. **你更常在哪两台之间切？** 台式机↔笔记本，还是笔记本↔平板/手机？这决定 v1.1.0 先枚举哪两台的窗口。
3. **你能接受“窗口搬运 = 重新打开文件/URL/应用”，而不是完整迁移应用状态吗？** 如果不能接受，v1.1.2 不做。
4. **Windows 先行是否可以？** 窗口枚举/聚焦先 Windows；Mac/Linux/Android 后续补。
