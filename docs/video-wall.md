## 0. 结论

| 问题 | 结论 |
|------|------|
| 叫什么 | **视频墙**，`ToolId = video-wall`，分组 `media`，包 `video-wall.flytool` |
| 能不能做 | **能做**。播放内核选 **libVLC** 打通「格式/协议覆盖」，二期用 **FFmpeg** 做「单画布合流 + 单流输出」，两者藏在同一个 `IMediaBackend` 后面可替换 |
| 最难的是什么 | 不是播放，是 **9 路同窗的资源与时钟**、**合流的语义边界**、**GB28181 / ONVIF 的国内私有差异**，以及 **90MB 级包体与 `.flytool` 内置策略的冲突** |
| 一句话取舍 | 一期只承诺「Windows 桌面 + 主流协议 + 1/4/9/16 宫格 + 画面合流」；「所有格式」按分级矩阵交付，不写绝对承诺 |

## 2. 定位与边界

### 2.1 定位

本机工具（`crossScreen=false`）。管的是**视频源**，不是**设备**：把「地址」变成「画面」，再把画面组织成「墙」。

| 项 | 值 |
|----|-----|
| `kind` | `enhancement` |
| `crossScreen` | `false`（一期不做跨机播放/转推） |
| `hasWorkspace` | `true`（主界面嵌入工具页工作区，不弹独立主窗） |
| `titleBar` | `false`（一期；播放/停止在工具页与工作区内，见 §7） |
| `supportsRepair` | `false`（原生库缺失按「包损坏」重装处理） |
| `capNames` | `[]`（不参与握手 Caps；一期不跨机） |
| `deviceClasses` | `["Desktop"]`（一期；手机/平板屏幕与解码预算不适合 9 宫格） |
| `platforms` | `["Windows"]`（一期；macOS / Linux 见 §6 分期） |

### 2.2 明确不做（MUST NOT）

- **不做采集/上屏**：把本机画面或摄像头采出去给别人，属于投影 / `shared-devices`，不并入本工具。
- **不做远程控制**：不注入键鼠、不调 PTZ 之外的设备能力（PTZ 属二期，且只走 ONVIF/GB28181 标准命令）。
- **不做转码服务器**：不监听公网端口给第三方拉流（可选的「推流输出」只作为客户端主动推，见 §6 P2）。
- **不做目录爬取**：MUST NOT 提供网段扫描 / 批量猜测地址 / 爆破口令。发现只允许用户显式触发的 ONVIF WS-Discovery 与 GB28181 注册。
- **不承诺 100% 格式**：MUST NOT 在文案里写「支持所有格式」；按 [video-wall-sources.md](video-wall-sources.md) 的分级矩阵对外表述。
- **不内置 DRM**：Widevine / PlayReady / FairPlay 一律不支持，遇到即明确报错（见 §8 错误分类）。

### 2.3 与既有能力的关系

| 既有能力 | 关系 |
|----------|------|
| 投影（`extended-display`） | 二期可选联动：把「合流后的单画面」投影到扩展屏 / 布局内对端，实现「一块大屏看九路」。复用宿主现有投影通道，工具只提供画面源，**不自己造投屏协议** |
| 共享设备 | 无耦合。共享摄像头是「把别人的摄像头当本机设备」，视频墙是「把任意地址当画面」 |
| 用户程序 / 无障碍 | 完全无关，工具不申请任何无障碍能力（符合 [tools.md](tools.md) §5.5.9） |

## 3. 需求

### 3.1 固定视频源（持久目录，MUST）

| 需求 | 规格 |
|------|------|
| 源类型 | 摄像头（USB/UVC 本机设备、IP 摄像头 RTSP/ONVIF）、NVR 通道、固定网络地址（HLS/RTMP/SRT/HTTP 文件）、本机文件 |
| 字段 | 名称、类型、地址、协议、认证（无/Basic/Digest/自定义 Header/Token 查询参数）、分组、备注、默认解码偏好（自动/硬解/软解）、重连策略 |
| NVR 批量 | 支持「基地址 + 通道模板」，如 `rtsp://{host}:554/Streaming/Channels/{ch}01`，一次生成 `ch=1..N`；支持主/子码流两套模板 |
| ONVIF 发现 | 用户点「发现设备」→ WS-Discovery（组播 239.255.255.250:3702）→ 列设备 → 选 Profile → 自动取 `GetStreamUri` 填入地址；MUST NOT 后台常驻扫描 |
| GB28181 接入 | 二期：SIP 注册 + 目录查询 + INVITE 拉流（详见 [video-wall-sources.md](video-wall-sources.md)） |
| 凭据存储 | 密码/Token MUST 用系统凭据保护（Windows DPAPI，macOS Keychain，Linux Secret Service）；MUST NOT 明文写进 scenes/日志 |
| 连通性测试 | 「测试」按钮 = 对应协议的轻量探测（RTSP `DESCRIBE` / HTTP `HEAD` 或首字节 / RTMP 握手），带 3s 超时与明确失败原因；**保存时另做一次首帧抓取**（见 §3.1.1） |
| 添加入口 | 工作区工具条「添加」按钮（拆分按钮：主按钮打开类型选择，下拉给常用类型快捷） |
| 展示方式 | **列表视图**（表格式、可多选批量操作）与**卡片视图**（封面 + 名称 + 状态，自适应换行）二选一，可切换并记忆上次选择 |
| 封面 | 每条源以**首帧**作封面图标；既作视觉占位，也作「这条配置是否正常」的判定依据（见 §3.1.1） |
| 导入导出 | 源清单可导出/导入 JSON（凭据默认剔除，可选「含凭据」并二次确认；封面默认不导出） |

#### 3.1.1 首帧封面与可用性判定（MUST）

| 项 | 规格 |
|----|------|
| 抓取时机 | ① 保存前（添加/编辑）；② 用户右键「刷新封面」；③ 连续 3 次连接失败后自动重抓一次；**不做**定时轮询抓帧 |
| 抓取方式 | 建一个临时播放会话，等首个完整帧（RTSP 等 IDR；HLS 取首个分片；文件 seek 到首个关键帧），**取到即停**，不进入常驻播放 |
| 超时 | 总体 8s；分协议建议：RTSP 5s、HLS 6s、RTMP 5s、file 2s、SRT 6s |
| 规格 | 320×180（16:9，按源比例 letterbox），JPEG 质量 80，单张约 15–30KB |
| 存储 | `covers/<key>.jpg`，key = `SHA256(protocol|address|transport|bufferMs|credentialRef)`；配置变更即换新 key，旧图清理 |
| 失效 | TTL 7 天；用户可手动刷新；源被删除时删除封面 |
| 失败策略 | 默认**允许保存但标记「未验证」**，封面用类型图标占位；勾选「必须验证通过才可保存」时阻断保存。失败原因用 §8 分类码展示 |
| 隐私 | 封面是本地文件，MUST NOT 上传；导出源清单默认不含封面；封面可能含画面内容，UI 提示「封面保存在本机」 |
| 刷新并发 | 批量刷新封面并发 ≤ 4（避免把 NVR / 出口带宽打满） |

> 说明：首帧失败 ≠ 地址永久不可用（可能是临时网络、设备正忙、签名过期）。因此默认不阻断保存，只用「未验证」角标区分；这一点与 [video-wall-sources.md](video-wall-sources.md) §7.1 的失败映射一致。

### 3.2 临时视频源（一次性，MUST）

| 需求 | 规格 |
|------|------|
| 入口 | 地址栏粘贴 + 回车即播；`Ctrl+O` 打开本地文件；窗口内拖放文件/URL 文本 |
| 协议识别 | 由 scheme 自动判定（`rtsp://` `rtmp://` `srt://` `udp://` `http(s)://` `file://` 或无 scheme 的本地路径），无 scheme 时按文件存在性判断 |
| 最近列表 | 保留最近 20 条（含协议、时间、成败），可一键重播；可清空 |
| 不落目录 | 临时源默认不进固定源目录；用户点「收藏为固定源」才落库 |
| HLS/直播课地址 | `m3u8` / `mpd` / 带 `.m3u8?...token` 的签名地址直接可播；签名过期导致的 403 要给出「地址可能已过期」提示 |

### 3.3 多屏播放（MUST）

| 需求 | 规格 |
|------|------|
| 布局 | `1×1` / `2×2` / `3×3` / `4×4`（最多 16 路）；另提供「主画面 + 侧栏小画面」比例布局（1 大 + 1~8 小），二期 |
| 一路一格 | 每格独立播放、独立状态、独立音量/静音、独立重连；MUST NOT 一处失败拖垮整墙 |
| 拖拽 | 源列表拖到空格即播；格间拖拽交换位置；拖出即停止该格 |
| 交互 | 双击格 → 单画面放大（其余暂停或降帧，可配）；右键菜单（全屏、静音、重连、关闭、复制地址、属性）；格内不放大面积控制条，控制条悬停出现 |
| 全屏 | 单格全屏、整墙全屏（大屏模式）；整墙全屏可指定显示器（多显示器场景，见 §7 宿主 API 增量） |
| 状态可视化 | 每格角标：`连接中 / 缓冲 / 播放 / 卡顿 / 重连 n / 失败`；格底部细条显示码率与分辨率 |
| 性能保护 | 超过预算（如 3×3 全 4K）时 MUST 提示并建议降级（降分辨率/停部分格/切硬解），MUST NOT 静默卡死 |

### 3.4 合流播放（MUST，语义见 §3.4.1）

用户原话：「多个视频合并为一个视频在一个播放器播放」。

| 需求 | 规格 |
|------|------|
| 合流画面 | 把当前墙的 N 路画面按布局合成为**一张**画面，在一个播放大区/独立视图里播放（可全屏、可全屏到指定显示器） |
| 合流即所见 | 合流结果 MUST 与墙上布局一致（含每格标题、状态角标可开关；默认关） |
| 音频策略 | 三选一：静音（默认）/ 单路独奏（选一格出声）/ 混音（全部出声，二期）。一期 MUST 至少实现前两种 |
| 布局切换不断流 | 1×1 ↔ 3×3 切换时已在播的源 MUST NOT 重建连接（只改渲染位置与尺寸） |
| 合流输出（二期） | 将合流画面编码为单流：存文件 / 推 `rtmp(s)://` `srt://` `rtsp://`（仅客户端推）。需要编码器，见 [video-wall-feasibility.md](video-wall-feasibility.md) §5 |

#### 3.4.1 合流的三种语义（必须区分，避免验收扯皮）

| 语义 | 定义 | 一期 |
|------|------|------|
| **A. 画面合流**（Canvas Composite） | N 路解码后的帧在 GPU 上合成到一张画布，作为「一个画面」呈现/输出 | **MUST（一期核心）** |
| **B. 输出合流**（Encode-Out） | 合流画布再编码成单条 H.264/H.265 流，落文件或推流 | 二期（P2） |
| **C. 码流合流**（Bitstream Mux） | 多路 ES 复用一个容器（如 MPEG-TS 多 PID） | **不做**；仅当多路编码/参数完全一致时理论可行，播放器侧还要选节目，产品价值低、兼容性差 |

**时钟**：以「墙」的主时钟为基准（默认第一路 `Playing` 的源为主时钟，可手动指定）。直播源之间通常有 200–2000ms 天然偏差，画面合流只保证**同一画布上的呈现时序不撕裂**，MUST NOT 承诺帧级严格同步；帧级同步仅在源带绝对时间戳（RTCP SR / PTP）时才可能做到，属 P2 研究项。

### 3.5 编码与协议

MUST 以 [video-wall-sources.md](video-wall-sources.md) 的矩阵为准。摘要：

| 维度 | 一期（P0） | 二期（P1/P2） |
|------|-----------|---------------|
| 协议 | file / http(s) 直链 / HLS / DASH(基础) / RTSP(RTP over TCP·UDP，Basic·Digest) / RTMP(S) / RTP·UDP 组播 / SRT | GB28181(SIP+PS)、ONVIF 发现+PTZ、WebRTC(WHEP)、RTSP over HTTP 隧道、SMB/FTP |
| 视频编码 | H.264、H.265/HEVC、MPEG-2、MPEG-4 Part2、MJPEG、VP8/VP9、AV1（dav1d）、VC-1/WMV3、ProRes、RV40 | VVC/H.266（依赖内核版本与硬件，暂不承诺） |
| 音频编码 | AAC、MP3、AC3/EAC3、Opus、Vorbis、FLAC、G.711 A/μ、G.722、AMR-NB/WB | 多路混音、声道选择 |
| 硬解 | D3D11VA（Windows），失败自动回软解并记录 | VideoToolbox / VAAPI（mac/Linux）、AV1/HEVC 硬解探测 |
| 不支持 | DRM（Widevine/PlayReady/FairPlay）、私有 SDK 封装、HLS 自定义密钥服务的非标准变体 | — |

### 3.6 场景与运维（SHOULD）

- **场景快照**：布局 + 每格绑定的源 + 音频策略 + 合流设置，命名保存；支持「启动时自动加载某场景」。
- **状态栏**：在线路数 / 总接收码率 / CPU / GPU / 内存 / 丢帧计数。
- **日志**：按格记录连接、首帧、重连、解码器、硬解回落原因；URL 必须脱敏（见 §8）。
- **自恢复**：进程内断流重连（指数退避 1s→30s，可配次数）；工具页「修复」不作必需（`supportsRepair=false`）。

## 5. 架构

### 5.1 分层

```text
FlyScreen 宿主（工具页 / 工作区 / 本地化 / 图标 / 安装器 / .flytool ALC）
        │  IToolModule / IToolHostServices / IToolUiHost
        ▼
FlyScreen.Tool.VideoWall                 ← 业务装配：Module、服务、场景、统计、日志
        ├── Sources/        源模型、地址解析与归一化、凭据、探测、导入导出
        ├── Wall/           布局、格位、状态机、音频路由、合流调度
        ├── Backend/        IMediaBackend 抽象 + 后端实现（vlc / ffmpeg）
        └── Contracts/      对外契约（UI 卫星与宿主共享）
        ▼
FlyScreen.Tool.VideoWall.Ui.Win / .Ui.Desktop / .Ui.Maui   ← 平台 UI 卫星（不写业务）
```

### 5.2 关键接口

```csharp
// 播放内核（可替换；一期实现 Vlc，二期实现 Ffmpeg）
public interface IMediaBackend
{
    string Name { get; }                 // "vlc" | "ffmpeg"
    Task<MediaProbeResult> ProbeAsync(MediaEndpoint endpoint, CancellationToken ct);
    IMediaPlayer CreatePlayer(MediaEndpoint endpoint, MediaPlayerOptions options);
    Task<IMediaCompositor?> CreateCompositorAsync(WallLayout layout, CancellationToken ct); // 仅 ffmpeg 返回
}

public interface IMediaPlayer
{
    TilePlayState State { get; }
    event Action<TilePlayState>? StateChanged;
    event Action<MediaStats>? StatsChanged;   // 码率/分辨率/丢帧/解码耗时
    Task StartAsync(CancellationToken ct);
    Task StopAsync();
    void SetVolume(int volume0To100);
    void SetMuted(bool muted);
}
```

设计要点：

1. **一个 libVLC 实例 + N 个 MediaPlayer**：MUST NOT 每格一个 `LibVLC` 实例（每实例约 40–60MB 固定开销）。
2. **后端只做「播放」，布局与业务在 `Wall/`**：换内核不改 UI 与场景数据。
3. **契约独立于 UI 框架**：`Contracts/` 只放模型 + 接口，UI 卫星与业务程序集共同引用，避免 WPF 类型泄漏进业务层。

### 5.3 渲染路径（两代，见 [video-wall-feasibility.md](video-wall-feasibility.md) §4）

| 代 | 做法 | 优点 | 缺点 |
|----|------|------|------|
| P0（libVLC） | 每格一个子窗口（`HwndHost` / `NativeControlHost`），由墙布局排列 | 落地快、格式覆盖一次到位 | 9 个 HWND；WPF airspace 限制（格上不能叠加任意 WPF 控件，需用独立浮层工具栏）；无法真正单画布合流 |
| P1（FFmpeg） | 单 D3D11 交换链，一窗合成 N 路纹理 | 单窗口零 airspace、合流天然成立、可再编码输出 | 自建播放器（时钟/seek/音画同步），开发量大 |

**结论**：一期若要「真合流」，必须先有 FFmpeg 合成路径；若一期只交付「九宫格 + 画面并排」，libVLC 足够。P0 的交付定义为**九宫格可用 + 合流视图按布局二次渲染**（见 §6 的 P0 收口说明），真单画布合流放 P1，避免一期被自研播放器拖死。

### 5.4 每格状态机（MUST）

```text
Idle → Resolving → Connecting → Buffering → Playing
                                  ↑  ├→ Stalled（3s 无新帧）→ Reconnecting（退避）
                                  └→ Failed（不可重试：401/404/不支持编码/DRM）
任意状态 → Stopping → Stopped
```

- `Failed` MUST 携带分类错误码与人类可读原因（见 §8）。
- 重连 MUST 只重建该格，MUST NOT 影响其它格与合流时钟（主时钟格重连时，时钟顺延到下一路）。
- 「自动重连」与「手动重连」共用同一入口，日志区分触发源。

### 5.5 数据模型（磁盘）

| 文件 | 位置 | 内容 |
|------|------|------|
| `video-wall.sources.json` | 工具数据目录（宿主 `FlyScreenDataPaths` 下工具专属子目录，**不放** ToolSdk） | 固定源目录 + 分组 |
| `video-wall.scenes.json` | 同上 | 场景快照 |
| `video-wall.recent.json` | 同上 | 最近 20 条临时源 |
| `video-wall.credentials.bin` | 同上 | DPAPI 加密的凭据表（不含明文） |
| 日志 | 宿主日志通道 `AppLog` | `video-wall` 前缀，URL 脱敏 |

字段与示例见 [video-wall-prototype.md](video-wall-prototype.md) §5。

### 5.6 进程模型

| 阶段 | 模型 | 理由 |
|------|------|------|
| P0 | 进程内（ALC 加载工具程序集 + 原生库进宿主进程） | 与现有工具一致，改动最小 |
| P1 | 可选外置引擎进程（`videowall-engine.exe`，命名管道/本地 socket 通信） | 原生解码器崩溃/驱动异常不再拖垮宿主；便于独立限流与 GPU 隔离 |

MUST：无论进程内还是外置，业务与 UI 只经 `IMediaBackend`，切换进程模型不改上层。

## 6. 实现路径与分期

以「1 名熟悉 WPF 的开发者」估算，含自测与打包，不含法务审计等待。

### P0-a：源管理 + 单条播放（**最先做**，目标 4 周）

这是用户可感知的第一块价值：先把「地址 → 一条记录 → 能播 → 有封面」这条闭环跑通，**不做九宫格、不做合流**。

| # | 内容 | 估时 |
|---|------|------|
| 1 | 工具骨架接入：`IToolModule`、卡片、工作区页签、本地化、图标、`manifest.json` | 0.5 周 |
| 2 | 源模型与地址归一化（[sources.md](video-wall-sources.md) §6 的 12 条规则）+ 固定源 CRUD + 分组 + 去重 | 1 周 |
| 3 | 添加流程：工具条「添加」→ 类型选择 → **按类型分表单**（字段与参数见 [prototype](video-wall-prototype.md) §3）→ 首帧抓取 → 保存 | 1 周 |
| 4 | 双视图：列表（表格 + 多选）与卡片（封面 + 状态），切换并记忆 | 0.5 周 |
| 5 | 单条播放视图：播放/停止/重连/全屏、信息条（编码/分辨率/码率/缓冲/首帧/丢帧/软硬解） | 1 周 |
| 6 | libVLC 后端最小集：单 `LibVLC` 实例、单/双 `MediaPlayer`、硬解探测与软解回落、首帧抓取复用同一解码路径 | （含在 3、5 内） |

**P0-a 收口定义**：能添加 4 类源（摄像头 / NVR 通道 / 网络地址 / 本机文件）各一条，保存后自动出封面；列表与卡片都能看到封面与状态；双击任一条能进入单条播放并稳定播放 30 分钟；编辑地址后封面随之更新；删除后本地封面文件一并清理。

> 只有 P0-a 通过，才投入 P0-b。**不要**在源管理还没闭环时就去做九宫格布局，否则墙的每一格都在替「源管理没做好」还债。

### P0-b：九宫格（目标 2 周）

| # | 内容 | 估时 |
|---|------|------|
| 7 | 1/4/9/16 布局、空格、拖拽入格与格间交换、单格全屏、整墙全屏 | 1.5 周 |
| 8 | 每格状态/角标/软解标记、性能预算闸门、非焦点格降帧 | 0.5 周 |

### P0-c：场景与交付（目标 2 周）

| # | 内容 | 估时 |
|---|------|------|
| 9 | 临时源（粘贴即播 / 拖放 / 最近 20 条）、快捷键 | 0.5 周 |
| 10 | 场景快照：布局 + 格绑定 + 音频策略，保存/加载/自动加载 | 0.5 周 |
| 11 | 打包与合规：`runtimes/win-x64` 裁剪插件、许可文本、体积优化、`Pack-FlyTools.ps1` 条目、回归清单 | 1 周 |

**P0 总收口定义**：九宫格稳定播放 1080p × 9 路 60 分钟不崩、单格失败不影响整墙、临时地址粘贴即播、场景可存可载、包可安装可卸载。**合流**在 P0 以「合流视图（按布局二次渲染的单画布输出到独立视图/全屏）」交付；真单画布 + 单流输出归 P1。

### P1：专业（目标 +6~8 周）

| # | 内容 | 估时 |
|---|------|------|
| 7 | FFmpeg 后端：单交换链合成、纹理级布局、合流输出（NVENC/QSV/AMF/VideoToolbox 编码，LGPL 合规） | 4 周 |
| 8 | ONVIF：WS-Discovery、Profile 选择、取流、PTZ | 1.5 周 |
| 9 | GB28181：SIP 注册/保活/目录/INVITE + PS over RTP 解复用 | 3 周（可与 7 并行） |

### P2：扩展

- 合流推流输出（`rtmp(s)` / `srt`）、多路混音、主画面比例布局、投影联动（合流画面投到扩展屏/对端）、macOS / Linux（VideoToolbox / VAAPI + 各自窗口嵌入）、Android（libvlc-android AAR + `SurfaceView`，竖屏单路/2 路为限）、VVC 评估。

### 6.1 建议的落地顺序（防止半套）

1. 先做 **单路稳定播放**（协议 + 硬解 + 重连 + 统计），这是所有后续能力的地基。
2. 再做 **九宫格与资源预算**（9 路并发是最容易暴露问题的场景）。
3. 再做 **源目录与场景**（产品化必须，但可以后置，避免早期被 UI 细节拖住）。
4. 最后做 **合流**（无论走「二次渲染」还是 FFmpeg 单画布，都依赖前面稳定）。

## 8. 错误分类（MUST，用于格内提示与日志）

| 分类码 | 触发 | 用户文案要点 |
|--------|------|-------------|
| `net.dns` | 域名解析失败 | 地址或 DNS 不可用 |
| `net.timeout` | 连接/握手超时 | 网络不可达或端口不通（给出协议与端口） |
| `net.reset` | 连接被重置 | 对端主动断开，将自动重连 |
| `auth.required` | 401 / Digest 失败 | 需要账号密码，或凭据错误 |
| `auth.forbidden` | 403 | 地址过期/无权限（HLS 签名地址最常见） |
| `src.notfound` | RTSP 404 / HTTP 404 / 通道不存在 | 路径或通道号错误（NVR 给出模板示例） |
| `src.unsupported` | 编码/封装不支持或 DRM | 明确说明「该编码/加密方式不支持」，附编码名 |
| `decode.hw.fallback` | 硬解初始化失败 | 提示已回软解；连续多格回落时建议更新显卡驱动 |
| `decode.failed` | 解码错误 | 码流损坏或参数异常 |
| `perf.overbudget` | CPU/GPU/显存超预算 | 建议降布局或降分辨率 |
| `io.disk` | 本地文件不可读 | 路径失效/权限 |

日志脱敏规则 MUST：`user:pass@` 段替换为 `***`；查询参数中 `token` / `sign` / `key` / `auth` 值替换为 `***`；完整 URL 只在「复制地址」用户主动操作时输出，且默认已脱敏（可显式「复制含凭据」并二次确认）。

## 9. 安全与合规

| 项 | 要求 |
|----|------|
| 凭据 | DPAPI/Keychain 加密；不写日志、不进场景导出（除非显式勾选） |
| 网络行为 | 只连用户显式添加的地址；MUST NOT 扫描网段、MUST NOT 上报任何地址到远端 |
| 许可 | libVLC：LGPL-2.1，动态链接 + 许可文本 + 可替换说明；FFmpeg：LGPL 构建（禁用 GPL 组件），编码走硬件编码器或 LGPL 兼容编码器；详见 [video-wall-feasibility.md](video-wall-feasibility.md) §5 与 `docs/THIRD_PARTY.md` 增量 |
| 插件裁剪 | 打包时剔除不用的 VLC 插件（x264 等 GPL 编码插件、无关输出模块），减少包体同时降低许可复杂度 |
| 卸载 | 停所有播放 → 释放原生句柄 → 注销 UI/图标/本地化 → 删安装目录；MUST NOT 残留 `libvlc` 句柄导致文件占用 |
| 无障碍 | 不申请、不持有（与 [tools.md](tools.md) §5.5.9 一致） |

## 10. 验收清单（P0）

### 10.0 源管理 + 单条播放（P0-a，先验收）

- [ ] 工具条「添加」可用；主按钮打开类型选择，下拉可按类型直达。
- [ ] 4 类源各有独立表单，字段随类型变化（对照 [prototype](video-wall-prototype.md) §3 的字段矩阵，多一个少一个都不算通过）。
- [ ] 条件字段正确显隐：认证≠无 → 显示用户名/密码；类型=NVR → 显示通道范围与模板；类型=本机文件 → 显示文件选择器。
- [ ] 保存时自动抓首帧：成功 → 卡片/列表显示封面；失败 → 显示类型图标 + 「未验证」角标 + §8 原因，且默认仍可保存。
- [ ] 卡片视图与列表视图都能显示封面、名称、类型、状态；切换后记忆选择。
- [ ] 双击任一条 → 单条播放视图；播放 30 分钟无崩溃，信息条数值随播放更新。
- [ ] 编辑地址并保存 → 封面按新 key 重抓，旧封面文件被清理。
- [ ] 删除源 → 记录与封面文件同时删除。
- [ ] 地址重复时提示「已存在：<名称>」，不静默新增。
- [ ] 封面文件仅存在于本机，导出源清单不含封面与凭据。

### 10.1 工具接入

- [ ] 工具页出现「视频墙」卡片，分组「媒体」，图标/名称/一句话说明正确；未安装/已安装/运行中三态底色正确。
- [ ] 单击已安装卡片 → 打开工作区页签（非弹窗）；运行中单击不停止，停止走 ⋯ 菜单。
- [ ] 卸载后：无残留原生句柄、目录可删、Caps 无变化（本工具不宣告 Cap）。
- [ ] 三端（Win / Desktop）至少编译通过；Maui 卫星可按清单过滤不显示（一期 `platforms` 仅 Windows）。

### 10.2 播放

- [ ] 临时地址粘贴即播：`rtsp://`（含 Digest）、`http(s)://…m3u8`、`rtmp://`、`srt://`、本地 `mp4/mkv/ts`。
- [ ] 固定源：新增/编辑/删除/分组、NVR 模板批量生成 N 路、连通性测试给出正确失败分类。
- [ ] 硬解失败自动回软解并提示；日志记录回落原因。
- [ ] 9 路 1080p25 同时播放 60 分钟：无崩溃、无内存持续增长（30 分钟采样漂移 < 10%）。
- [ ] 单格断网重连成功，其它 8 格不受影响；`Stalled` 3s 判定生效。
- [ ] 认证失败/404/不支持编码给出 §8 对应文案，不出现空白格无提示。

### 10.3 墙与交互

- [ ] 1/4/9/16 布局切换，已在播的源不断流。
- [ ] 拖拽入格、格间交换、拖出停止；双击单画面放大再返回，位置与状态保持。
- [ ] 整墙全屏、单格全屏；退出全屏恢复原布局。
- [ ] 性能超预算时出现提示，可选择降级且立即生效。

### 10.4 合流（P0 口径）

- [ ] 合流视图与墙布局一致；可全屏；标题/角标可开关（默认关）。
- [ ] 音频策略：静音 / 单路独奏可用；切换不卡顿。
- [ ] 布局切换后合流视图同步更新，不重启播放。
- [ ] 文档与界面均不宣称「帧级同步」。

### 10.5 数据与安全

- [ ] 场景保存/加载/删除、启动自动加载某场景。
- [ ] 导出 JSON 不含凭据；勾选含凭据时二次确认。
- [ ] 日志 URL 已脱敏；凭据文件非明文（十六进制/DPAPI 头可见）。
- [ ] 无任何网段扫描行为（代码审查 + 抓包确认）。
