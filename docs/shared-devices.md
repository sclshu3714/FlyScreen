## 1. 规则

有摄像头、麦克风、扬声器的电脑或手机，可以分别作为提供方；没有对应设备的电脑可以作为使用方。

例如：台式电脑本身没有摄像头、麦克风、扬声器，可以使用手机的摄像头、麦克风、扬声器。

三条能力互相独立，对应工具页上三个独立工具，各自安装、卸载。

## 2. 入口：工具页（不是高级设置）

不在高级页做开关组。入口见 [tools.md](tools.md)：

- 侧栏「程序」下增加「工具」。
- 分组「共享设备」下三条：共享摄像头、共享麦克风、共享扬声器。
- 用户动作只有 **安装** 与 **卸载**。没有启动、没有停止。
- 筛选：全部 / 未安装 / 已安装。正在被会议等软件使用时，卡片可标「使用中」，仍只能卸载。

装完即按本章规则工作：选定提供方、注册虚拟设备；本机软件打开摄像头或麦克风时才采集；扬声器有声音写入时才转发。用户不必再点启动。

## 3. 与投影声音

投影中的声音同步只在投屏会话里，把正在播放的声音送到对端，并尽量让提供方扬声器不出声。共享扬声器是没有扬声器的电脑把系统播放接到对端的真实扬声器上，对端本地播放不静音。共享摄像头、共享麦克风是没有该硬件的电脑在系统里多出一个设备，供会议等其它软件选用。

不复用 `ScreenExtendAudio`。那条消息绑定投影会话，并带有静音本机扬声器的语义。

## 4. 角色

| 角色 | 谁 | 做什么 |
|------|----|--------|
| 提供方 | 本机有真实摄像头、麦克风或扬声器的电脑或手机 | 安装对应工具 = 允许共享该路；采集或播放，服务一台使用方 |
| 使用方 | 本机没有该种真实设备的电脑 | 安装对应工具 = 装虚拟设备组件并选定提供方；供本机其它软件选用 |

第一期使用方只做 Windows 桌面（WPF 与 Maui-Win 同一套行为）。提供方做 Windows 与 Android 手机。Mac / Linux / 鸿蒙工具卡片可见，安装提示尚未支持。手机不作使用方。

一路硬件同时只服务一台使用方。第二台来开时拒绝，原因 `busy`。

## 5. 怎样判断「没有该设备」

只统计操作系统枚举到的真实硬件，排除玄鸟自己注册的虚拟摄像头、虚拟麦克风、虚拟扬声器。否则虚拟设备一创建，使用方就变成「有设备」，共享会自己断开。

| 种类 | 视为没有 |
|------|----------|
| 摄像头 | 没有视频采集设备 |
| 麦克风 | 没有状态为活动的录音端点 |
| 扬声器 | 没有状态为活动的播放端点；只剩显示器自带的 HDMI / DisplayPort 音频也视为没有 |

未插上的插孔、已禁用的端点、玄鸟自己的虚拟设备都不算。工具卡片上另有「本机没有可用的麦克风」「本机没有可用的扬声器」。检测把显示器音频当成扬声器时，用户打开对应项，这台电脑改按使用方处理。

有真实硬件：卡片按提供方展示（安装 = 允许共享）。没有真实硬件，或用户标明本机没有：卡片按使用方展示（安装 = 装组件并选提供方）。只有一路提供方时自动选定；选定不等于开始采集。

## 6. 安装与卸载（本三条工具）

`AppSettings`（或工具安装状态存储）记录三条是否已安装，以及使用方选定的提供方机器名。不进 `BehaviorSync`。

| 角色 | 安装 | 卸载 |
|------|------|------|
| 使用方 · 摄像头 | Win11 注册虚拟摄像头；记下提供方 | 结束会话，卸虚拟摄像头 |
| 使用方 · 麦克风 / 扬声器 | 安装虚拟音频组件（缺则提示安装，可能要管理员）；注册「玄鸟麦克风 / 扬声器」；记下提供方；无真实喇叭时可将玄鸟扬声器设为默认并记下原默认 | 结束会话；若默认设备仍是玄鸟则恢复；卸虚拟端点与组件（按组件要求） |
| 提供方 · 任一 | 允许共享该路；摄像头 / 麦克风申请权限（拒绝则安装失败，保持未安装） | 关闭允许共享；进行中的会话结束；停前台服务（若无其它路仍在共享） |

无工具级启动 / 停止。会话随软件打开或关闭虚拟设备而建立或结束，见第 7 节。

## 7. 会话

1. 提供方在安装状态变化、插拔硬件、连接建立时，向已连接对端发 `SharedDeviceState`（控制通道）。
2. 使用方已安装且本机软件打开虚拟摄像头 / 麦克风，或有声音写入虚拟扬声器时，发 `SharedDeviceOpen`。
3. 提供方 `SharedDeviceAccept` 后开始采集或准备播放。拒绝则 `SharedDeviceReject`。
4. 媒体走 Bulk。对端没有 `BulkTransfer` 时直接拒绝，不把视频和音频退回控制通道。
5. 软件关闭设备、卸载工具、提供方卸载、拔掉硬件或断连 → `SharedDeviceClose`，两端都停。

摄像头、麦克风、扬声器各算一路会话，可以同时开。例如台式机同时用手机的镜头、麦和音箱。

与投影的关系：

- 摄像头、麦克风可以和投影同时开。两条会话独立。Bulk 上音频优先于画面，画面优先于文件，见第 14 节。
- 投影声音同步只向从机的真实播放设备送声音，不写入玄鸟虚拟扬声器。从机没有真实播放设备时不静音主机，声音留在主机。共享扬声器继续只传输从机应用自己播放的声音。

## 8. 协议

旧端忽略未知 `MessageType`，不断连。能力位表示「这个版本会处理这些消息」。某一路是否真的可开，以运行时的 `SharedDeviceState` 为准，不写进握手 Caps。

| Cap | 含义 |
|-----|------|
| `SharedCameraProvider` / `SharedMicProvider` / `SharedSpeakerProvider` | 本版本能作为提供方 |
| `SharedCameraConsumer` / `SharedMicConsumer` / `SharedSpeakerConsumer` | 本版本能注册对应虚拟设备 |

第一期：Windows 桌面六个都宣告。Android 只宣告三个 Provider。Mac / Linux / 鸿蒙暂不宣告。

| MessageType | 值 | 通道 | 方向 | 载荷 |
|-------------|----|------|------|------|
| `SharedDeviceState` | 90 | Control | 提供方 → 各对端 | JSON：`Camera` / `Mic` / `Speaker` 是否可开，以及显示名 |
| `SharedDeviceOpen` | 91 | Control | 使用方 → 提供方 | JSON：`Kind`（camera / mic / speaker）、`SessionId` |
| `SharedDeviceAccept` | 92 | Control | 提供方 → 使用方 | JSON：`SessionId`、`Kind`、采样率 / 声道 / 宽高 / 帧率 |
| `SharedDeviceReject` | 93 | Control | 提供方 → 使用方 | JSON：`Kind`、`Reason`（`busy` / `off` / `no-device` / `no-bulk`） |
| `SharedDeviceClose` | 94 | Control | 任一方 | JSON：`SessionId`、`Kind`、`Reason`（`preempted` / `capture-lost` / 空为正常关闭） |
| `SharedDeviceVideo` | 95 | Bulk | 提供方 → 使用方 | 二进制：16 字节 SessionId + 序号 + JPEG |
| `SharedDeviceAudio` | 96 | Bulk | 见下 | 二进制：16 字节 SessionId + 序号 + PCM s16le |

`SharedDeviceAudio`：麦克风为提供方 → 使用方；扬声器为使用方 → 提供方。音频第一期 48000 Hz、s16le、单声道、约 20 ms 一块。视频第一期 1280×720、15 fps、JPEG。

## 9. 使用方：让其它软件看得见

| 种类 | Windows 做法 |
|------|----------------|
| 摄像头 | Windows 11 用户态 Media Foundation 虚拟摄像头（`MFCreateVirtualCamera`），本进程送帧。不新写内核驱动 |
| 麦克风 | 「玄鸟麦克风」录音端点，写入收到的 PCM |
| 扬声器 | 「玄鸟扬声器」播放端点，读出应用写入的 PCM，经 Bulk 发给提供方 |

麦克风 / 扬声器需要可再分发的虚拟音频组件，对照虚拟显示：随包离线、工具安装时检测，缺了再装；检测硬件时不改系统默认设备。Windows 10 第一期可不承诺虚拟摄像头；虚拟音频若支持 Win10，麦克风和扬声器可单独可用。

虚拟设备友好名带提供方机器名。已安装后设备出现在系统里；本机软件打开摄像头或麦克风才 `Open`，最后一个客户端关闭就 `Close`。扬声器有写入时打开，空闲约 2 秒关闭。

无真实播放设备时，已安装期间把玄鸟扬声器设为默认并记下原值；卸载、断开或退出且默认仍是玄鸟时恢复。用户中途改过默认设备则不再改。投影播放不跟随该默认设备。

麦克风只写入虚拟麦克风；扬声器只转发虚拟播放设备上的声音。

另一玄鸟进程已注册同名虚拟设备时，本进程不再注册，工具卡片说明原因。卸载、退出时卸掉本进程注册的设备。崩溃后音频组件在用户态客户端消失后输出静音。

## 10. 提供方：采集、播放与权限

| 种类 | Windows | Android |
|------|---------|---------|
| 摄像头 | Media Foundation 默认摄像头 | Camera2 / CameraX；共享期间前台服务（摄像头） |
| 麦克风 | WASAPI 默认录音 | `AudioRecord`；前台服务（麦克风） |
| 扬声器 | WASAPI 播放，与本机声音混合，不静音 | `AudioTrack` 媒体流，与本机声音混合 |

权限在提供方点安装时申请；拒绝则安装失败。正在被使用时通知栏前台通知；卸载或全部会话结束后停前台服务。

本机软件占用镜头或麦时本机优先，共享以 `preempted` 结束；本机放开后若使用方虚拟设备仍开着再重新 `Open`。

采集被打断时发 `capture-lost`：使用方麦改为静音、摄像头停最后一帧，托盘提示；恢复后继续。

同一提供方同时作麦和音箱时打开平台回声消除；平台没有则仍可用并提示可能有回声。

共享扬声器的播放不进投影回环采集。

## 12. 实施顺序

1. 工具页壳（侧栏、分组、筛选、安装/卸载空卡片）+ 三条共享设备入口。
2. 摄像头：Android 提供方 + Windows 11 使用方。
3. 麦克风：虚拟录音端点。
4. 扬声器：方向相反的音频。
5. Windows 提供方与手机提供方共用会话服务。

每步：旧端不断连；卸载后系统里不再收到数据；投影声音同步行为符合第 14 节。

## 13. 第一期不做

- 工具级启动 / 停止。
- 高级页共享设备开关组。
- 手机、Mac、Linux、鸿蒙作为使用方。
- 本机已有真实摄像头时再改用别人的镜头。
- 选择非默认物理镜头或麦克风。
- H.264、通用降噪（同一设备麦+音箱的回声消除要做）。
- 共享流做成用户程序 API；一路硬件分给多台电脑。

## 14. 与现有功能的冲突

不处理时的结果；对应规则在第 15 节。

### 14.1 有设备的电脑向没有设备的电脑投影并开声音同步

甲有三路硬件且三条工具已安装（提供方）。乙三路都没有且可已安装使用方工具。甲向乙投影并勾选声音同步。

共享安装不会改投影语义。声音同步仍只采集甲的播放、尽量静音甲扬声器、送到乙的真实播放设备。不采集麦克风，画面不是摄像头。

乙没有真实播放设备时，投影声音在乙侧播不出。若乙已安装共享扬声器，投影从机若误写入玄鸟扬声器会送回甲，造成无声或回声。

### 14.2 其它问题

| 问题 | 不处理时的结果 |
|------|----------------|
| HDMI / 未插入插孔被当成有设备 | 只能当提供方，用不了手机麦和音箱 |
| 不设默认播放设备 | 有其它端点时声音走不到玄鸟扬声器 |
| 一安装就常开采集 | 耗电、占硬件、隐私 |
| 本机软件与共享抢镜头 / 麦 | 需明确谁优先 |
| 同一手机既麦又音箱 | 无回声消除会啸叫 |
| 与投影 / 文件抢 Bulk | 画面与传输变卡；键鼠在控制通道不受影响 |
| 锁屏杀采集 / 退出留死设备 / 双进程注册 | 会议选到无数据设备或注册失败 |
| Mac/Linux 从机无扬声器 | 第一期不能做使用方；声音同步需单独处理 |

## 15. 解决规则

### 15.1 投影声音同步和共享扬声器

投影声音只播到从机真实播放设备，永不写入「玄鸟扬声器」。

从机没有真实播放设备时：不静音主机，不向从机发投影音频；提示「对方没有扬声器，声音留在本机」；已安装的共享扬声器继续只传从机应用自己的声音；主机投影回环排除这段共享播放。

从机有真实播放设备时：声音同步照旧，播放端点选真实设备。

两种先后顺序都用这一条。手机做投影主机同样适用。

示例结果：甲的投屏声音留在甲；乙自己的声音仍可经共享扬声器从甲播出；镜头和麦仅在乙上软件打开虚拟设备时采集。

### 15.2 其余问题

| 问题 | 规则 |
|------|------|
| 误判有扬声器 / 麦克风 | 只认活动端点；仅 HDMI 音频视为无扬声器；卡片提供「本机没有可用的…」强制使用方 |
| 默认播放设备 | 无真实喇叭时，已安装期间设玄鸟为默认；卸载或退出且仍是玄鸟时恢复；用户改过则不恢复 |
| 采集时机 | 安装只注册与选定；软件打开设备才 `Open`；关掉就 `Close`；扬声器有写入才开，空闲约 2 秒关 |
| 本机抢硬件 | 本机优先，`preempted`；放开后若虚拟设备仍开着再 `Open` |
| 同一设备麦+音箱 | 允许；开平台回声消除；否则提示可能有回声 |
| Bulk | 堆积时丢旧音视频块；优先级：音频 → JPEG → 文件 |
| 采集中断 | `capture-lost`；麦静音、摄像头末帧；恢复后续传 |
| 退出 / 卸载 | 卸本进程虚拟设备；音频客户端消失后静音 |
| 装虚拟声卡 | 仅用户点该工具「安装」且组件缺失时安装；检测与投影环境检查不装、不改默认 |
| 双进程 | 同名已注册则后启动者不再注册，卡片说明 |
| Mac/Linux 无扬声器从机 | 不做使用方；第 15.1 节「声音留在本机」仍生效 |
