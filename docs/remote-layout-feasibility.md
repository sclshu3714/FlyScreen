# 异地电脑加入布局并投影：可行性分析（v1.1.0 起）

| 项 | 内容 |
|----|------|
| 性质 | 可行性分析 + 分期建议，不含代码改动 |
| 日期 | 2026-11-11 |
| 场景 | 3 台电脑 + 1 台手机/平板；其中 2 台电脑 + 手机/平板在公司局域网并已加入布局；第 3 台电脑在家里；要把家里电脑加入布局，并投影到指定的公司电脑 |
| 结论 | **可实现**，但需要新增“远程设备接入/传输层”；现有局域网发现与 4 台布局不能直接跨公网工作。最快验证路径是外部虚拟局域网（Tailscale/ZeroTier/WireGuard）+ 手动地址；产品化再做内置远端入口与中继 |

---

## 0. 一句话结论

**投影本身不是瓶颈，网络可达才是。**

- 现有投影是 1 对 1：Host 采集 → Sink 全屏显示，走已连接 peer 的 Bulk 通道。只要家里电脑和指定公司电脑能建立 TCP 连接，投影协议就能跑。
- 现有布局是局域网语义：UDP 发现、同网段、最多 4 台、边缘键鼠。家里电脑不在公司局域网，**不会被发现，也不能直接加入布局**。
- 因此要实现你的场景，必须补一层“异地设备接入”：先解决家里电脑怎么被公司电脑连上，再谈布局槽位与投影。

---

## 1. 场景拆解

| 设备 | 位置 | 现状 | 目标 |
|------|------|------|------|
| 公司电脑 A | 公司局域网 | 已连接、已入布局 | 作为投影目标之一 |
| 公司电脑 B | 公司局域网 | 已连接、已入布局 | 可作为投影目标/网关 |
| 手机/平板 | 公司局域网 | 已入布局（不参与布局广播主路径） | 保持现状 |
| 家里电脑 C | 家里，非公司 LAN | 不在布局、不可被发现 | 加入布局第 4 槽；作为投影源，投到指定公司电脑 |

**数量**：2 台公司电脑 + 1 台手机/平板 + 家里电脑 = 4 台，未超过现有 4 台上限。若未来要 3 台公司电脑 + 手机 + 家里电脑 = 5 台，需要改上限与布局协议。

**方向**：家里电脑 C 作为 **Host**（采集），指定公司电脑（A 或 B）作为 **Sink**（全屏显示）。反向（公司投到家里）也能做，只要家里电脑宣告 `ScreenExtendSink`。

---

## 2. 现有能力与缺口

### 2.1 已有，可直接复用

- 4 台设备上限、1×4 / 2×2 布局、槽位同步。
- 1 对 1 投影：`ScreenExtendOffer/Accept/Reject/Stop/Frame`，Host/Sink 能力位，Bulk 帧通道，JPEG（质量约 80），声音同步，远程回控。
- 手动添加 peer 的入口（如果现网只支持“发现后添加”，则需要补一个“远端地址”入口，约 1–2 周）。
- 共享安全密钥/信任模型（可复用，但跨公网需要更强的会话加密与设备认证）。

### 2.2 缺口

| 缺口 | 说明 | 影响 |
|------|------|------|
| 发现 | 现有 UDP 发现是局域网广播；家里电脑不在同一广播域 | 家里电脑不会出现在发现列表 |
| 传输 | 现有 TCP 直连假设双方 IP 可达；家庭宽带多为 NAT/CGNAT，公司网络可能禁止入站 | 没有公网 IP/端口映射时连不上 |
| 布局语义 | 布局/边缘键鼠假设低延迟局域网；跨公网边缘切换会明显卡 | 家里电脑不宜作为普通穿边 peer |
| 投影质量 | 现有 JPEG 约 12fps；跨公网带宽/延迟更紧张 | 静态办公可用，视频/动画会卡 |
| 安全 | 跨公网暴露端口风险高；共享密钥不足以做公网身份 | 需要会话加密、设备认证、临时信任 |
| 休眠/重连 | 家里电脑可能睡眠/断网/换 IP | 需要自动重连、唤醒、地址更新 |

---

## 3. 四种网络方案

| 方案 | 做法 | 需要什么 | 代码量/周期 | 适用与风险 |
|------|------|----------|-------------|------------|
| **A. 外部虚拟局域网**（Tailscale / ZeroTier / WireGuard） | 家里电脑与指定公司电脑装同一 overlay，获得虚拟 IP；FlyScreen 用手动地址连虚拟 IP:15155 | 两端能装客户端；公司允许；账号/管理 | **0–2 周**（若手动添加可用） | 最快验证；不改变产品定位；依赖第三方；公司 policy 可能禁止 |
| **B. 内置手动远端地址** | 在 FlyScreen 里新增“远端地址”入口：输入 IP:端口/域名，不走发现，直接 TCP 连接 | 两端网络可达（overlay/端口映射/IPv6） | 1–2 周 | 产品化第一步；仍需解决可达性 |
| **C. 内置中继 / NAT 穿透** | 家里与公司都主动连中继（STUN/TURN/HTTPS 443），中继转发控制/帧 | 公网中继服务器、账号/设备认证、带宽成本 | 6–10 周（MVP） | 真正零配置；改变“局域网、无云”定位；隐私/成本/公司 policy |
| **D. 端口映射 / IPv6 直连** | 家里路由器把 TCP 15155 映射到家里电脑；公司电脑连公网 IP/IPv6 | 家里有公网 IP 或 IPv6；公司允许出站 | 0–1 周（配置） | 最快但最不安全；CGNAT 不可用；不建议作为产品方案 |

**建议顺序**：先用 A 验证“投影跨公网是否可用”；可用后做 B 的产品化入口；只有当用户不愿装 overlay/公司禁止时，才考虑 C 中继。

---

## 4. 投影可行性

### 4.1 协议层

- 现有投影是 **1 对 1**：家里电脑 C（Host）→ 指定公司电脑（Sink）。
- 前提：C 与 Sink 之间有一条已建立的 peer 连接（TCP 15155 控制 + Bulk）。
- 如果 C 只连到公司电脑 B（网关），但要投到公司电脑 A，现有协议没有“经 B 转发到 A”的路由；需要：
  - 让 C 直接连到 A（推荐：A 也装 overlay/可达）；或
  - 增加网关转发/中继（新能力，复杂）。
- **结论：投影到“指定的一台电脑”，最稳的做法是让那台电脑与家里电脑直接可达，而不是只让一台公司电脑做网关。**

### 4.2 画质/延迟

- 现有 JPEG 约 12fps、质量 80；1080p 单帧约 100–300KB，12fps 约 10–30Mbps；家庭上行 20–50Mbps 可跑，4K 更紧张。
- 跨公网 RTT 通常 10–50ms（同城）到 100ms+（跨省/跨运营商）；加上编码/解码/显示，端到端约 50–150ms。
- 静态办公/文档/代码：可用；视频/动画/游戏：不够，需要 H.264/E2 + 自适应码率/分辨率/丢帧。
- 声音同步：PCM 走 Bulk；跨公网需要抖动缓冲；语音可用，音乐/低延迟不合适。
- 远程回控：输入事件跨公网 50–150ms；点击/打字可用，快速操作/游戏不行。

### 4.3 布局语义

- 如果把家里电脑当普通布局槽，边缘键鼠切过去会明显卡；不建议。
- 建议新增 **“远程槽位/远程设备”** 语义：
  - 出现在布局/设备列表中，带“远程”标记；
  - **默认不参与边缘穿边**，不作为 EdgeMouse 目标；
  - 投影目标选择里可选它；
  - 需要操作时，用“远程控制”按钮单独进入，并显示延迟提示；
  - 断线自动重连，不阻塞本地 3 台设备的正常穿边。
- 这样既满足“加入布局”的可见/可管理，又不把高延迟设备混进低延迟穿边拓扑。

## 5. 最快验证（不改代码）

目标：先确认“家里电脑与公司电脑之间能不能跑现有投影”，再决定是否产品化。

1. 在家里电脑 C、指定公司电脑 A 上安装同一个 overlay（Tailscale/ZeroTier/WireGuard），加入同一虚拟网络。
2. 记录 C/A 的虚拟 IP；在公司电脑上 `Test-NetConnection <C虚拟IP> -Port 15155`，确认 TCP 可达。
3. 在 FlyScreen 里用“手动添加/远端地址”填 C 的虚拟 IP:15155；两端填同一安全密钥。
4. 在 C 上发起投影（复制模式）→ 选 A 作为目标；观察是否能出画面。
5. 记录：首帧时间、帧率、操作延迟、断线重连、声音是否可用。
6. 再把 A 换成 B（另一台公司电脑）重复一次，确认“投到指定电脑”是否需要每台都装 overlay。

**判定**：
- 能出画面、帧率可接受、断线能重连 → 场景成立，值得产品化。
- 连不上/帧率不可用 → 先解决网络（overlay/中继），不要先改投影。

## 6. 产品化分期

### v1.1.0 远程设备接入（最小可用）

- 新增“远端地址/远程设备”入口：输入 IP:端口/域名，不走发现，直接连接。
- 远程设备在设备列表中可见，带“远程”标记；可加入布局的第 4 槽，但默认不参与边缘穿边。
- 复用现有安全密钥/信任；增加“仅本次会话”的临时信任。
- 投影目标选择里可选远程设备；先支持“家里 → 公司”的复制投影。
- **周期**：3–4 周（含手动入口、远程槽位、投影选择、断线提示）。
- **验收**：家庭宽带 + 公司网络（允许出站）下，手动地址能连上；投影首帧 <5s；1080p 静态画面可读；断线自动重连。

### v1.1.1 远程投影体验

- 分辨率/帧率自适应；带宽/延迟指示；低带宽降分辨率/帧率；断线重连；声音同步可选。
- 远程设备作为 Sink 时，显示“远程投影”角标与延迟。
- **周期**：2–3 周。
- **验收**：同城 20–50ms RTT 下，1080p 文档/代码可读；带宽 10Mbps 时自动降级不花屏。

### v1.1.2 远程控制（可选）

- 远程设备作为被控端：键鼠/触控输入跨公网；延迟提示；只对已信任设备开放。
- 默认关闭；需要显式开启；会话到期自动关闭。
- **周期**：2–3 周。
- **验收**：点击/打字可用；不用于游戏/高频操作。

### v1.1.3 内置中继/NAT 穿透（战略级，可选）

- 家里与公司都主动连中继（443/TURN）；无公网 IP 也能连；端到端加密；设备认证。
- 这会改变“局域网、无云”的产品定位，需要单独论证成本/隐私/公司 policy。
- **周期**：6–10 周（MVP）。
- **不建议先做**：先用 overlay 验证需求，再决定是否自建中继。

## 7. 风险与边界

| 风险 | 说明 | 对策 |
|------|------|------|
| 公司网络 policy | 可能禁止 VPN/第三方 overlay/入站端口 | 先确认 IT 政策；只做出站 443 中继；不绕过 |
| 家庭 CGNAT | 没有公网 IP，端口映射不可用 | 用 overlay 或中继 |
| 延迟/带宽 | 跨省/跨运营商 RTT 高；上行不足 | 自适应分辨率/帧率；H.264/E2；明确“静态办公可用，视频不够” |
| 安全 | 跨公网暴露端口；共享密钥弱 | 端到端加密；设备认证；临时信任；不裸奔 TCP |
| 4 台上限 | 3 公司电脑 + 手机 + 家里 = 5 台 | 先按 4 台；要 5 台需改布局/协议 |
| 平台 | 家里电脑可能是 Mac/Linux；投影 Host 支持有限 | Windows 先行；Mac/Linux 按现有采集能力降级 |
| 休眠/换 IP | 家里电脑睡眠/宽带重播 IP | 自动重连；overlay 地址稳定；唤醒可选 |

---

## 8. 需要你确认

1. **公司网络允许装 Tailscale/ZeroTier/WireGuard 吗？** 如果不允许，只能走 443 中继，周期和成本都会上去。
2. **家里宽带有公网 IP 或 IPv6 吗？** 还是 CGNAT？这决定是否需要 overlay/中继。
3. **你要的是“看”还是“操作”家里电脑？** 看 → 投影；操作 → 远程控制，延迟要求不同。
4. **指定投影的那台公司电脑，是唯一能出网的机器，还是多台都能出网？** 如果只有一台，投到另一台需要网关转发/中继；建议让目标电脑也具备可达性。
5. **家里电脑是 Windows 还是 Mac/Linux？** Windows 先行最稳；Mac/Linux 的 Host 采集能力按现有矩阵降级。
