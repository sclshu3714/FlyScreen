## 0. 优先级与结论

**先做「源管理 + 单条播放」，九宫格与合流后置。**

理由：九宫格的每一格都在消费「源」这条记录。源字段、地址归一化、首帧封面、单条播放的稳定性没跑通时，墙只会把问题放大 9 倍，且难以定位是哪一格、哪条配置的问题。

```text
P0-a（本文件主体，4 周）       P0-b（2 周）            P0-c（2 周）
源管理 ⇄ 单条播放 ⇄ 首帧封面  →  1/4/9/16 宫格      →  临时源/场景/打包
```

本版原型只覆盖 **P0-a**；九宫格与合流的线框保留在 §6，作为后置参考。

## 2. 源管理页

### 2.1 工具条

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ [列表|卡片]   [🔍 搜索名称/地址…]   分组[全部 ▾]  排序[名称 ▾]   ＋添加 ▾     │
└──────────────────────────────────────────────────────────────────────────────┘
```

| 元素 | 规格 |
|------|------|
| 视图切换 | 分段控件（列表 / 卡片），记住上次选择（本机设置，不进场景） |
| 搜索 | 输入即筛（名称 + 地址，地址匹配时忽略凭据段）；`Esc` 清空 |
| 分组筛选 | 全部 / 各分组 / 「未分组」；新增分组在添加弹窗里完成 |
| 排序 | 名称 / 最近播放 / 添加时间（卡片视图同样生效） |
| **＋添加** | **拆分按钮**：主按钮（较大）打开「类型选择」；下拉给 `摄像头` / `NVR 通道` / `网络地址` / `打开本机文件` 四个直达项，直达时跳过类型选择 |
| 多选 | 仅列表视图：`Ctrl+点击` 累加、`Shift+点击` 连选；有选中时工具条右侧出现 `批量删除` / `移动分组` / `刷新封面` |
| 空选中 | 不显示批量操作，避免误触 |

## 3. 添加流程（P0-a 核心）

### 3.1 三步

```text
[工具条 ＋添加]
   ↓
① 类型选择（4 张卡）  ──（下拉直达时跳过）──┐
   ↓                                        │
② 按类型表单（字段随类型变化）               │
   ↓                                        │
③ 抓首帧（8s 上限） → 预览封面 → 保存         ┘
```

- 步骤可回退（`上一步`），但回退即丢弃已抓封面。
- 抓帧期间显示进度条与「正在读取首帧…」，**不允许**重复提交。
- 抓帧失败：显示失败原因 + `[重试]` + `[仍然保存（标记未验证）]`；若用户在设置里勾了「必须验证通过才可保存」，则只显示 `[重试]` `[取消]`。

### 3.2 类型选择

```text
┌─ 添加视频源 ────────────────────────────────────────────────┐
│  选择类型                                                    │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────┐│
│  │   📷        │ │   🖥        │ │   🌐        │ │   📁    ││
│  │  摄像头      │ │  NVR 通道   │ │  网络地址    │ │ 本机文件 ││
│  │ RTSP / IP   │ │ 批量按通道  │ │ HLS/RTMP/SRT│ │ 本地/共享││
│  └─────────────┘ └─────────────┘ └─────────────┘ └─────────┘│
│                                       [取消]  [下一步 →]     │
└──────────────────────────────────────────────────────────────┘
```

> ONVIF / GB28181 属 P1，一期**不出现在**类型选择里（避免「点了却不能用」）。

#### B. NVR 通道（`NvrChannel`）

**一条 NVR 记录 = 一次批量生成 N 条通道记录**（不做「NVR 主机」这一层实体，避免 P0-a 引入树形管理）。

```text
┌─ 从 NVR 批量添加 ───────────────────────────────────────────┐
│ 主机*     [ 192.168.1.100 ]   端口* [ 554 ]                  │
│ 认证      [ Digest ▾ ]  用户名 [ admin ]  密码 [ •••••• ]     │
│ 码流      (•) 主码流  ( ) 子码流                             │
│ 通道范围* [ 1 ] – [ 16 ]     命名模板 [ 通道-{ch2} ]          │
│ 地址模板* [ rtsp://{host}:{port}/Streaming/Channels/{ch}01 ]  │
│ 缓冲      [ 800 ] ms      解码 [ 自动 ▾ ]                    │
│ 分组      [ NVR ▾ ]                                           │
│                                                              │
│ 预览（16 条）              [并发 4 抓帧]  ●12 ⚠3 ✕1            │
│  ☑ 通道-01  rtsp://…/101   ● H.264 1080p                     │
│  ☑ 通道-02  rtsp://…/201   ● H.264 1080p                     │
│  ☐ 通道-09  rtsp://…/901   ✕ 401 认证失败（该条不勾选）        │
│                                                              │
│                        [取消]  [添加选中的 15 路]              │
└──────────────────────────────────────────────────────────────┘
```

| 字段 | 控件 | 必填 | 默认 | 校验 / 说明 |
|------|------|------|------|-------------|
| 主机 | Text | ✅ | — | 主机名或 IP；不含 `rtsp://` |
| 端口 | Number | ✅ | 554 | 1–65535 |
| 认证 | Select | — | Digest | 无 / Basic / Digest |
| 用户名 / 密码 | Text / Password | ✅（认证≠无） | `admin` | — |
| 码流 | Radio | ✅ | 主码流 | 主/子；影响模板里的 `{ch}01` / `{ch}02` 或 `subtype` |
| 通道范围 | Number×2 | ✅ | 1–16 | `from ≤ to`，跨度 ≤ 64（防误填 1–9999） |
| 命名模板 | Text | — | `通道-{ch2}` | 占位符 `{prefix}` `{ch}` `{ch2}` |
| 地址模板 | Text | ✅ | 厂商默认 | 必须含 `{ch}` 或 `{ch2}`；不支持 `{user}`/`{pass}` 明文 |
| 缓冲 / 解码 / 分组 | — | — | 同摄像头 | 应用到本批所有通道 |

**生成规则**：

- 一条通道 = 一条独立的 `NvrChannel` 记录（各自有 id、封面、状态），编辑其中一条不影响其它通道。
- 批量抓帧并发 ≤ 4；失败的条默认**不勾选**，但允许用户手动勾上强制添加。
- 若所有通道都失败，弹「疑似模板或认证不正确」并提供「换个模板试试」。

| 字段 | 控件 | 必填 | 默认 | 条件 / 校验 |
|------|------|------|------|-------------|
| 名称 | Text | ✅ | 地址末段 | ≤ 64 |

```text
│ 文件*   [ D:\video\demo.mkv                  ] [浏览…]         │
```

| 字段 | 控件 | 必填 | 默认 | 校验 / 说明 |
|------|------|------|------|-------------|
| 文件 | 文件选择器（`OpenFileDialog`）+ 手填 | ✅ | 空 | 存在性 + 可读性；支持 UNC；扩展名白名单见 sources §2 |

| 循环播放 | Checkbox | — | 关 | 播放结束行为（P0-a 只在单条播放生效） |

> 「拖文件到窗口」属 P0-c 的临时源能力；P0-a 只做对话框里的浏览选择，避免两套入口同时上线。

### 3.4 条件显示与校验（实现要点）

| 规则 | 行为 |
|------|------|
| `type == NvrChannel` | 隐藏「地址」「厂商预设」；显示「主机/端口/通道范围/模板/预览表」 |
| `type == LocalFile` | 隐藏「认证/传输/缓冲」，地址换成文件选择器 |
| `type == NetworkUrl` | 隐藏「传输方式/厂商预设」；显示「协议覆盖/自定义 Header」 |
| `auth != none` | 显示用户名/密码（必填） |
| `protocol == rtsp` | 显示「传输方式」；否则隐藏（保留值但不生效） |
| 校验时机 | 失焦校验单字段；点「保存」全量校验；错误定位到第一个非法字段并滚动到可见 |
| 错误展示 | 字段下方红字（不用 toast）；同一字段只显示一条最高优先级错误 |

### 3.5 保存动作（顺序固定）

```text
1. 归一化地址（凭据抽出 → 凭据表；协议/默认端口/脱敏）
2. 去重检查（同 protocol + 同归一化地址）→ 命中则提示「已存在：<名称>」，可「仍要添加」
3. 抓首帧（8s）→ 得封面 key + 尺寸/编码/分辨率（NVR 批量按条抓，并发 4）
4. 写 sources.json（含 coverKey / coverCapturedAt / validationState）
5. 写封面文件 covers/<key>.jpg
6. 刷新列表/卡片；新记录置顶并选中；提示「已添加」并可「立即播放」
```

任一步失败：不写半条记录；已抓的封面若未保存成功则删除，避免孤儿文件。

```text
└──────────────────────────────────────────────────────────────────────┘
```

| 项 | 规格 |
|----|------|
| 进入方式 | 双击列表行 / 卡片；或卡片 `⋯` → 播放 |
| 画面 | 单画面 `Uniform` 适配，可右键切 `cover`/`fill` |
| 控制条 | **不在视频面内**（airspace 限制），放顶部一行 + 底部信息条 |
| 信息条 | 编码 / 分辨率 / 帧率 / 码率 / 缓冲 / 首帧耗时 / 丢帧 / 软硬解 |
| 全屏 | 单格全屏，`Esc` 退出；全屏时信息条与标题行自动隐藏（鼠标移动 2s 后淡出） |
| 停止 | `← 返回列表` 或工具条 `停止`；停止即释放播放器，不保留后台连接 |
| 失败 | 画面区居中显示 §8 分类原因 + `[重试]` `[编辑地址]`，不留黑屏 |
| 音频 | 默认**静音**（P0-a）；用户点「静音」按钮切换，音量固定 100 或上次值 |

**编辑即时生效**：从播放视图点「编辑地址」→ 保存后回到播放视图并自动重连；若地址变了，封面同步重抓。

## 5. 首帧封面管线（实现规格）

```text
[保存 / 刷新封面]
   ↓
ProbeSession（临时会话，非常驻播放器）
   ↓  按协议取首帧：RTSP 等 IDR · HLS 取首个分片 · 文件 seek 关键帧
Frame(原始分辨率)
   ↓  缩放 + letterbox
320×180 → JPEG q80 (~15–30KB)
   ↓
covers/<key>.jpg      key = SHA256(protocol|address|transport|bufferMs|credentialRef)
   ↓
sources.json 记 coverKey / coverCapturedAt / validationState
```

| 项 | 规格 |
|----|------|
| 尺寸 | 320×180（固定 16:9，非 16:9 源加黑边，不裁切） |
| 质量 | JPEG q80；单张 15–30KB；100 条约 2–3MB |
| 缓存键 | 配置哈希；`credentialRef` 变化也算变（避免换账号后仍显示旧画面） |
| 清理 | 源删除即删；启动时清理无主封面（可选，P0-c） |
| 并发 | 刷新并发 ≤ 4 |
| 解码 | 抓帧走**同一条**后端解码路径（P0-a 单条播放已验证的能力），不另起第二套解码器 |
| 失败 | 保留旧封面（若有）并标 `未验证`；无旧封面则用类型图标 |
| 隐私 | 本机文件；不上传；导出不含 |

**关键设计**：抓帧与播放复用同一 `IMediaBackend`，只是「取一帧就停」。这样首帧成功 ≈ 播放成功，封面天然成为「配置是否正常」的判据，不需要第二套探测逻辑。

## 8. 状态视觉

| 状态 | 列表 | 卡片 | 说明 |
|------|------|------|------|
| `未播放过` | ○ 灰 | 灰点 | 新添加但未真正播放 |
| `正常` | ● 绿 | 绿点 | 最近一次播放/抓帧成功 |
| `未验证` | ⚠ 黄 | 黄点 + 封面降饱和 | 抓帧失败但有旧封面，或从未验证成功 |

| `播放中` | ▶ 蓝 | 蓝点 | 仅当前正在播放的那一条 |
| `软解` | 角标 `sw` | 角标 `sw` | 硬解回落时附加显示 |
| `需要认证` | 🔒 橙 | 橙点 | `auth.required`，提示去编辑凭据 |

规则：状态 = 最近一次动作（抓帧或播放）的结果 + 连续失败计数；MUST NOT 用「文件时间」或「猜测」判断。

## 9. 空 / 错状态

| 场景 | 文案与操作 |
|------|-----------|
| 无源 | 见 §2.4 |
| 搜索无结果 | `没有匹配「xxx」的源` + `[清除搜索]` |

```json
        "protocol": "rtsp",

      },
```

| 新增字段（相对 v0.1） | 说明 |
|----------------------|------|

| `lastPlayedAt` | 排序与「最近」列 |

